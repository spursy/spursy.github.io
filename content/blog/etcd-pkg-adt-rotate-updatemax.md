[上一篇](/blog/etcd-pkg-adt-interval-tree/)讲了区间树的**查询侧**:`Insert` 沿下降路径埋 `max`,`Intersects` / `Stab` 用 `max` 整片剪掉不可能重叠的子树。但那篇的 demo 是一棵**未平衡的普通 BST**,刻意省掉了红黑树的旋转——于是留了个尾巴:真实 etcd 靠旋转自平衡,而**旋转会改变节点的子树成员,缓存的 `max` 就过期了**。

这篇补上**维护侧**:旋转后如何重算 `max`、为什么必须从下层节点起算、以及 `updateMax` 那行不起眼的提前终止如何把最坏 O(树高) 的更新压到 O(1~2)。两篇合起来,才是完整的区间树。

## 一、问题:为什么旋转后非重算 max 不可

先回顾:区间树 = 红黑树 + 每节点缓存 `max`(以本节点为根的子树内所有区间 End 的最大值)。红黑树靠 `rotateLeft` / `rotateRight` 做自平衡,而**旋转会改变两个节点的子树成员**:

```
       x                        y
      / \                      / \
     a   y     --左旋(x)-->    x   c
        / \                  / \
       b   c                a   b
```

旋转前 `x` 的子树 = `{a, b, c, x}`,旋转后 `x` 的子树只剩 `{a, b, x}`;`y` 的子树反过来变大。两个节点的「覆盖范围」都变了,缓存的 `max` 于是过期。

若不重算,后续查询的 max 剪枝就会基于错误的 `max` 做判断——**该进的子树被剪掉(漏查),或该剪的子树进去了(白费)**。所以旋转的指针手术做完后,必须紧跟一步 max 重算。

## 二、旋转代码:指针手术 + 一行 updateMax

demo 的 `rotateLeft`(镜像的 `rotateRight` 把 left/right 互换):

```go
func (t *Tree) rotateLeft(x *node) {
	y := x.right
	if y == nil {
		return
	}
	x.right = y.left          // 中间子树 b：从 y 的左，换挂到 x 的右
	if y.left != nil {
		y.left.parent = x
	}
	y.parent = x.parent
	if x.parent == nil {
		t.root = y
	} else if x == x.parent.left {
		x.parent.left = y
	} else {
		x.parent.right = y
	}
	y.left = x                // x 落到 y 的左边
	x.parent = y
	// ★ 从下层的 x 开始向上：先修 x，再修此刻已成为 x 父节点的 y，再修祖先。
	t.updateMax(x)
}
```

前面十几行是标准红黑树旋转的指针手术(保持有序性不变,只调树形)。**真正和区间树相关的只有最后一行 `t.updateMax(x)`**——这是普通红黑树没有、区间树必须多做的一步。对齐真实 etcd `interval_tree.go` 的 `rotateLeft`(:599、:606),它甚至在旋转中途和末尾各调一次。

## 三、核心设计 1:必须从「下层的 x」起算,顺序不能反

`updateMax(x)` 这行有个容易忽略的讲究:**参数为什么是下层的 `x`,而不是上位的 `y`?**

因为旋转后 `x` 落到 `y` 的下面(`x` 成了 `y` 的孩子)。重算必须**自底向上**:先算 `x`,再算 `y`。理由是 **`y` 的 max 依赖 `x` 子树的 max**——若先算 `y`,它会读到 `x` 的**旧(过期)** max,算错。

demo 的 `demo3` 用一个极端场景把这点演示得很直白:

```
先算上层 y：y.max=20（错！用了 x 的过期 max=20，漏掉 x 真实的 100）
先算下层 x（x.max=100）再算 y：y.max=100（对！）
→ 结论：updateMax 从下层 x 出发向上走，天然保证这个顺序。
```

场景是:`x` 的真实子树最大 End 是 100,但它缓存的 `max` 还停在过期的 20。此时:

- **先算上层 `y`**:`y` 读到 `x.max=20`,于是把自己算成 20 —— 漏掉了 `x` 子树里真实的 100。
- **先算下层 `x`**:先把 `x.max` 修成 100,`y` 再读到正确的 100。

而 `updateMax` 的实现正是**从传入的节点出发、沿 parent 链向上走**,所以只要传下层的 `x`,就天然保证「先 x、再 y、再祖先」的正确顺序——不需要额外协调。

## 四、核心设计 2:updateMax 的提前终止

`updateMax` 本身是这样的:

```go
func (t *Tree) updateMax(x *node) {
	for x != nil {
		old := x.max
		m := x.end
		if x.left != nil && x.left.max > m {
			m = x.left.max
		}
		if x.right != nil && x.right.max > m {
			m = x.right.max
		}
		if old == m { // ★ 提前终止：本节点 max 没变，祖先必然也不变
			break
		}
		x.max = m
		x = x.parent
	}
}
```

它沿 parent 链向上逐个重算。**关键优化是 `if old == m { break }`:一旦某节点重算后 max 没变,就断定它所有祖先也不会变,立即停。**

### 为什么「我不变」能推出「祖先都不变」

这靠 `max` 的**单调性**——越往上(越靠近根),节点的 max 越大(祖先覆盖的子树更大,父节点 max 是各子树 max 的最大值)。

设这次变动引入的 End 值叫 `E`。向上走到某节点 `A` 发现 max 没变,意味着 `E ≤ A.max`(E 没突破 A)。再看 A 的父亲 `P`:

```
P.max ≥ A.max ≥ E
```

`E` 连 `A` 都没突破,就更不可能突破本就更大的 `P` —— P 必然不变。同理一路到根,全都不变。**所以在 A 处就能安全 break,上面的结论已被传递性锁死,不必再逐个验证。**

直觉上,新 End 就像往水里扔石头的波纹:它只能影响那些「原本 max 比它小」的节点,一旦遇到第一个「max ≥ 它」的祖先,波纹被吸收,再往上传不动了——**变化沿树上浮,但会自然收敛**。

### demo2:小 End 走 1 层,大 End 传到根

```
插入 [1,2)（end 很小）：updateMax 只走访了 1 个节点（提前终止）
插入 [16,40)（end 超大）：updateMax 走访了 3 个节点（传播到根）
```

- 插入 `[1,2)`,E=2:落点父节点 `[0,3)` 的 max=3 已盖住(2 ≤ 3),重算不变 → **只走 1 层**。上面 `[5,8).max=9`、根 `[15,23).max=30` 都盖得住,逻辑上无需去看。
- 插入 `[16,40)`,E=40:一路突破所有祖先的 max,`break` 永不触发 → **传播到根,走 3 层**。

这就是提前终止的价值:把最坏 O(树高) 的向上更新,在多数插入/旋转里压到只走 1~2 层。

## 五、验证:旋转后 max 依然全部正确

demo 每次操作后用「暴力重算子树真实 max」逐节点校验缓存值。左旋根节点 `[15,23)` 后:

```
左旋后：
        [25,30) max=30
[19,20) max=30
                [17,19) max=19
        [15,23) max=23
                        [8,9) max=9
                [5,8) max=9
                        [0,3) max=3
  ✓ 所有节点 max 正确
```

(横向打印:右子树在上、左子树在下,缩进=深度,头向左歪 90° 看即正常树。)

注意 `[15,23)` 旋转后子树缩小,`max` 从旋转前的 30 **正确地降到了 23**——这正说明 `updateMax` 不只会「抬高」,也能在子树变小时算出更小的正确值(重算是整体取 max,不是单向累加)。整棵树 `✓ 所有节点 max 正确`。

## 六、这是增强树的通用范式

区间树 max 的这套维护逻辑,适用于任何在节点上缓存「子树聚合值」的**增强树(augmented tree)**——只要那个聚合值满足「父节点值由子节点值决定」:

| 增强字段 | 聚合方式 | 提前终止 |
|---------|---------|---------|
| 区间树 `max` | 子树最大 End | 重算后不变即停 |
| 子树和 `sum` | 左 + 右 + 自身 | 增量为 0 时可停 |
| 子树计数 `size` | 左 + 右 + 1 | 一般每次必变,难提前停 |

区间树 `max` 特别适合提前终止,因为「取最大」天然满足「小值被大值吸收」。范式可以概括成一句:

> **增强红黑树 = 红黑树 + 「每次结构变动(插入/删除/旋转)后,从受影响的下层节点起、沿 parent 链向上重算增强字段,并在字段稳定时提前终止」。**

## 七、总结

- **旋转必然使 max 过期**:旋转改变父子子树归属,被旋转的两节点覆盖范围变了,缓存 max 要重算。
- **重算从下层节点起**:`updateMax(x)` 传下层的 `x`,沿 parent 链上行,天然保证「先算子、再算父」——先算父会读到子的过期值而算错。
- **提前终止是点睛之笔**:`if old == m { break }` 利用 max 向上单调递增的性质,新 End 一旦被某祖先盖住就停止传播,把 O(树高) 压到 O(1~2)。

配合[上一篇](/blog/etcd-pkg-adt-interval-tree/)的查询侧,现在可以完整回答区间树为什么能稳定 O(log n):**红黑旋转保证树高不退化 → 旋转后 updateMax(带提前终止)高效维护 max → 查询时用 max 剪枝**。三者环环相扣,缺一不可。
